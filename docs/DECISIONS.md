- D-001: Use the official `gnani-vachana` SDK rather than raw REST unless a required capability is missing. Revisit if the SDK cannot support the required request.
- D-002: Load FLEURS source files through `huggingface_hub`; do not use `datasets.load_dataset` or remote code.
- D-003: Use SQLite through SQLAlchemy for a reproducible local benchmark with no database service setup.
- D-004: Use deterministic synthetic noise and simulated telephony rather than real customer calls; this protects privacy and improves reproducibility but limits external validity.
- D-005: Normalize every STT input to mono PCM16 at 16 kHz before calling the API.
- D-006: Use one explicit output format across both models only if both support it. Otherwise label the comparison non-equivalent or stop the controlled comparison.
- D-007: Format selection is pending the M2 pilot; record evidence and rationale before benchmarking.
- D-008: Use Python 3.12 in `.venv` with exact pinned versions of the 14 approved dependencies (`gnani-vachana==0.9.0`, etc.) to guarantee reproducibility.
- D-009: Server-Enforced Live Authorization Policy (Fail-Closed). Context: Client requests could pass `live=1` and trigger accidental cloud billing. Options: A) Trust client parameter, B) Server-enforced environment variable. Chosen: Option B (`ALLOW_LIVE_API=0` default). Any client `live=1` request without explicit server authorization raises HTTP 403 Forbidden (`LIVE_EXECUTION_FORBIDDEN`). Revisit if multi-tenant per-user billing is introduced.
- D-010: Relational Call Persistence & Durable Audio Asset Lifecycle. Context: Audio recordings and metadata were lost across application restarts. Options: A) File-only storage with predictable MD5 filenames, B) Relational SQLite schema (`recording_sessions`, `audio_assets`, `transcripts`, `followup_records`) with random UUID filenames (`ast_{uuid}.wav`) and SHA-256 integrity verification. Chosen: Option B. Audio is persisted before upstream STT execution to prevent data loss on provider timeouts. Revisit if cloud object storage (S3) is adopted.
- D-011: Application-Level WebSocket Audio Transport with Buffered REST Transcription. Context: Upstream Gnani Prisma STT operates via atomic HTTP REST (sub-200ms batch). Options: A) Fabricate provider-side incremental streaming events in the UI, B) Provide truthful application-level WebSocket audio transport buffering chunks and executing atomic REST transcription. Chosen: Option B. Preserves architectural honesty without fabricated streaming illusions. Revisit if Gnani introduces a native gRPC/WebSocket streaming endpoint.
- D-012: Curated 7 Indic Voices Catalogue for Gnani Timbre. Context: Historical documentation mentioned 42 voices, while 7 curated voices were exposed. Options: A) Retain speculative 42-voice claim, B) Reconcile documentation and UI to reflect the 7 curated Indic voices (`Pranav`, `Kaveri`, `Ishaan`, `Devika`, `Lavanya`, `Deepak`, `Trisha`) with flagship male `Pranav` and female `Kaveri`. Chosen: Option B. Revisit if upstream adds verified voice endpoints.
- D-013: Human-in-the-Loop Follow-up Desk with Strict Missing-Field Tracking. Context: Autonomous collections risk generating wrongful reminders if dates or amounts are hallucinated. Options: A) Autonomous reminder generation with fallbacks, B) Operator review workflow with explicit missing-field tracking (`missing_fields: ["Promise-to-pay date"]`). Chosen: Option B.
